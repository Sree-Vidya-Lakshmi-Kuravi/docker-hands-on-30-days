## Docker Container Interaction, Debugging & Monitoring Commands

### 1. docker exec
- Purpose: Executes a new command inside an already running container without stopping or restarting it.
- Syntax: docker exec [OPTIONS] CONTAINER COMMAND [ARG...]
- Example: docker exec -it my-nginx /bin/bash
Opens an interactive Bash shell inside the running my-nginx container.
- When to use it: Use this when you need to step inside a running container to troubleshoot issues, inspect files, test network connectivity, or run one-off administrative scripts. Exiting this session will not stop the container.

### 2. docker attach
- Purpose: Connects your local terminal's standard input, output, and error streams (STDIN, STDOUT, STDERR) directly to the main foreground process (PID 1) of a running container.
- Syntax: docker attach [OPTIONS] CONTAINER
- Example: docker attach my-app
Attaches your terminal directly to the primary running process of my-app.
- When to use it: Use this when you want to view live console output or interact directly with a container's main process that was originally started in detached (-d) mode. (Caution: Pressing Ctrl + C while attached will usually stop the container unless detached cleanly using Ctrl + P followed by Ctrl + Q).

### 3. docker logs
- Purpose: Retrieves and displays the console logs (STDOUT and STDERR) generated by a container's main process.
- Syntax: docker logs [OPTIONS] CONTAINER
- Example: docker logs -f --tail 100 my-nginx
Displays the last 100 lines of logs from my-nginx and continues streaming new log entries in real time.
- When to use it: Use this as your first step for debugging application errors, checking startup messages, or monitoring live traffic logs—even if the container has already crashed and stopped.

### 4. docker inspect
- Purpose: Returns detailed, low-level configuration and runtime state information about Docker objects (containers, images, networks, volumes) in JSON format.
- Syntax: docker inspect [OPTIONS] NAME|ID [NAME|ID...]
- Example: docker inspect my-nginx
Outputs the full JSON metadata for my-nginx, including its IP address, mounted volumes, environment variables, and restart policy.
- When to use it: Use this when you need to find a container's internal IP address, verify port bindings, check volume mount paths, or diagnose why a container exited unexpectedly (via its exit code).

### 5. docker stats
- Purpose: Displays a live, real-time stream of resource usage statistics for one or more running containers.
- Syntax: docker stats [OPTIONS] [CONTAINER...]
- Example: docker stats my-nginx
Streams live CPU percentage, memory usage/limit, network I/O, and block (disk) I/O metrics for my-nginx.
- When to use it: Use this to monitor container performance in real time, detect memory leaks, or identify containers consuming excessive CPU or bandwidth.

### 6. docker top
- Purpose: Displays the running processes inside a container, similar to the standard Linux ps or top command.
- Syntax: docker top CONTAINER [ps OPTIONS]
- Example: docker top my-nginx
Lists all active processes, their Process IDs (PIDs), users, and execution times running inside my-nginx.
- When to use it: Use this to quickly verify which background processes or worker threads are active inside a container without needing to exec into it—especially useful for minimal containers that lack shell utilities like ps or bash.

### 7. docker wait
- Purpose: Blocks the terminal prompt until one or more specified containers stop running, and then prints their exit status codes.
- Syntax: docker wait CONTAINER [CONTAINER...]
- Example: docker wait batch-job-container
Pauses your terminal until batch-job-container finishes its task and exits, returning 0 on success or a non-zero error code on failure.
- When to use it: Use this in automation scripts or CI/CD pipelines when you need a script to pause and wait for a background task container to complete before moving on to the next step.
